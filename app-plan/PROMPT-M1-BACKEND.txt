DATAMODEL (hoofdstuk 4 is leidend; dit zijn de vaste keuzes erbij)
- Veldnamen en enum-waarden in het NEDERLANDS, precies zoals hoofdstuk 4.
- hh_users = auth-collectie. Velden: rol (select: hulpvrager, jongere,
  familie, coordinator), naam, telefoon, geboortedatum (date), foto (file,
  1 bestand, alleen image/*), wijk (relatie hh_wijken), taal (select: nl,
  ar, tr, en; default nl). E-mail verplicht, telefoonverificatie is een
  later punt.
- hh_klussen.status = select met exact de acht waarden: concept, open,
  geaccepteerd, onderweg, bezig, afgerond, geannuleerd, probleem.
- hh_klussen.bron = select: app, telefoon, familie.
- hh_betalingen.status = select: open, betaald, mislukt, terugbetaald.
- hh_profielen: één per gebruiker, unieke index op gebruiker.
- hh_koppelingen: unieke index op (oudere, familielid).
- hh_vertrouwd: unieke index op (oudere, jongere).
- hh_push_tokens: unieke index op token.
- Bedragen als number in centen (integer). Geen required op number-velden
  waar 0 geldig is (PB weigert 0 bij required, zie valkuil 10).
- Elke collectie: autodate created + updated.
- Relaties: cascadeDelete alleen op hh_klus_status, hh_push_tokens en
  hh_profielen (verwijder gebruiker = verwijder afgeleide rijen). Elders
  cascadeDelete=false; hh_klussen, hh_betalingen en hh_incidenten mogen
  nooit stil verdwijnen.

API-RULES (principes; werk ze per collectie uit en leg ze vast in SCHEMA.txt)
- Nergens een lege rule ("" = publiek). Elke rule vereist minstens
  @request.auth.id != "". Uitzondering: hh_klustypes en hh_wijken zijn
  leesbaar voor elke ingelogde gebruiker, schrijfbaar alleen coordinator.
- rol-check altijd expliciet met = en ||, nooit ~.
- hulpvrager: ziet en bewerkt eigen hh_klussen (hulpvrager = auth.id),
  eigen profiel, eigen koppelingen, eigen beoordelingen. Ziet nooit
  bedragen-velden van anderen; ziet geen andere ouderen.
- jongere: ziet hh_klussen met status open in eigen wijk (wijk-relatie
  gelijk aan auth.wijk) plus klussen waar toegewezen_jongere = auth.id.
  Kan status wijzigen op eigen toegewezen klus. Kan open klus accepteren
  (toegewezen_jongere leeg -> auth.id). Het exacte status-overgangsschema
  wordt later in een hook bewaakt; in M1 alleen: jongere mag bedrag_bruto,
  vergoeding_jongere, commissie, hulpvrager en geplaatst_door NIET wijzigen
  (@request.body.X:isset = false).
- familie: alles wat de gekoppelde oudere ziet, via
  @collection.hh_koppelingen (oudere ?= record.hulpvrager && familielid
  ?= auth.id). Plaatst klussen namens de oudere met geplaatst_door =
  auth.id en bron = familie.
- coordinator: volledige toegang op alle hh_.
- Anti-escalatie: op hh_users mag een gebruiker zichzelf bijwerken maar
  niet rol (@request.body.rol:isset = false). Alleen coordinator zet rol.
  Zelfregistratie (createRule) mag met rol hulpvrager, jongere of familie;
  coordinator kan alleen door coordinator worden aangemaakt. Als dat niet
  in één rule past: createRule = alleen niet-coordinator-rollen, en zet in
  OPEN-PUNTEN dat coordinator-accounts handmatig/superuser worden gemaakt.
- hh_klus_status: create door deelnemer van de klus (hulpvrager,
  toegewezen_jongere, gekoppeld familielid) of coordinator; nooit update
  of delete behalve coordinator.
- hh_betalingen, hh_vergoedingen: lezen door betrokkene, schrijven alleen
  coordinator (Mollie-hook komt in M16).
- hh_incidenten: aanmaken door elke deelnemer, lezen door melder +
  coordinator, bewerken alleen coordinator.
- hh_push_tokens: eigen rijen alleen.
- Multi-relatievelden: altijd `.id ?=`, nooit kaal `?=` (valkuil).
- Test elke bewering hieronder in 04-rulecheck: positief EN negatief
  (mag wel / mag niet). Minstens: oudere A ziet klus van oudere B niet;
  jongere ziet open klus in eigen wijk wel, in andere wijk niet; jongere
  kan bedrag niet wijzigen; familielid ziet klus van gekoppelde oudere wel,
  van ongekoppelde niet; gebruiker kan eigen rol niet ophogen; anoniem
  krijgt op elke hh_-collectie 400/403/404, nooit 200.

REGELS
- Dry-run eerst, altijd. Print wat je ZOU doen voor je --apply draait.
- Idempotent: tweede keer draaien mag niets breken en niets dupliceren.
- Hard-guard in elk script: weiger elke collectienaam die niet met hh_
  begint. Ook in de backup-vergelijking.
- Geen hooks, geen server-restart, geen ssh in M1. Alles via de REST-API
  vanaf de Mac.
- Verzin geen extra collecties of velden. Twijfel -> OPEN-PUNTEN.txt.
- GIT: git-root is de map buurthulp. De index bevat staged wijzigingen
  buiten backend/ die niet van jou zijn, en een tweede agent commit
  tegelijk onder app/. Daarom: nooit git add -A; stage alleen backend/
  en commit uitsluitend met pathspec:
  git -C "/Users/h/Desktop/huidige projecten/buurthulp" add backend/...
  git -C "/Users/h/Desktop/huidige projecten/buurthulp" commit -m "feat: ..." -- backend
  Krijg je index.lock: 2 seconden wachten en opnieuw, niet de lock
  verwijderen.
- backend/.gitignore: node_modules, backups/, .env, *.local.*
- Commits: feat/fix/chore. Nederlands in commentaar en SCHEMA.txt.
