KEUZES DIE IK MAAKTE
  - Eigen collectie hh_ouder_toestemming (één rij per helper) in plaats van
    velden op hh_users: de helper leest zijn eigen hh_users-rij, dus hashes,
    IBAN en ouder-naam horen daar niet. Het resultaat (ouder_toestemming_op,
    ouder_iban_ok) staat wel op hh_users; daar kijken rule en hook al naar.
  - Code (6 cijfers) en link-token (40 tekens) alleen als sha256; de code
    gaat nooit naar de app of in een log. Geen geheime sleutel op de server
    nodig (zou een instelling op prod zijn): code verloopt na 24 uur en na
    5 fouten, dus raden kan niet.
  - De link (#/ouder?t=...) slaat de code-stap over zolang de code geldig
    is: link en code staan in dezelfde mail, de token staat achter de #
    (nooit in een serverlog of Referer) en de toestemming vraagt daarna nog
    naam, IBAN en het vinkje. Na 24 uur toont de link alleen de stand;
    intrekken met de link kan altijd. Zonder link: e-mail + code.
  - Elke nieuwe mail geeft een nieuwe code EN een nieuwe link; de oude link
    werkt dan niet meer ("gebruik de nieuwste mail").
  - Max 3 mails per dag per helper (UTC-dag), 30 publieke verzoeken per IP
    per uur. Een mislukte mail (SMTP) telt niet mee.
  - Afzender (antwoord 1): naam "HeitjeHulp" per bericht; adres uit
    HH_MAIL_AFZENDER, anders het globale adres (nu info@bovexa.nl).
  - Intrekken (antwoord 2): klussen op geaccepteerd/onderweg komen vrij in
    dezelfde transactie (logregel door "systeem", toelichting "ouder trok
    toestemming in"); bewoner krijgt de bestaande "We zoeken iemand
    anders". Een klus die al BEZIG is blijft staan.
  - Na intrekken (antwoord 3): kind kan niet zelf opnieuw mailen (409
    ingetrokken, "De meldkamer neemt contact met je op."). De meldkamer
    geeft vrij met de route /api/hh/ouder/vrijgeven, in het paneel de knop
    "Kind mag ouder opnieuw mailen" (screening-detail). Een echte wachtrij
    "ingetrokken" voor de meldkamer is B11.
  - Aanmeldveld (antwoord 4): alleen "E-mailadres van je ouder"; een
    eerder bewaard ouder_telefoon blijft op de server staan.
  - Status voor de app via een 5e route GET /api/hh/ouder/status (de app mag
    de collectie niet lezen).
  - App: na aanmelden onder 18 eerst de stap "Ouder" (mail gaat meteen,
    "Stuur opnieuw", adres wijzigen), dan "Je aanmelding". Op Start komt de
    ouder-balk nu VOOR "wordt nagekeken"; na toestemming verdwijnt hij (of
    volgt "wordt nagekeken"). Ingetrokken heeft een eigen melding.
  - Wie in B2 alleen een nummer gaf, krijgt bij de stap Ouder "Vul ook het
    e-mailadres van je ouder in" (K1); het nummer blijft bewaard.
  - AVP-vinkje is niet verplicht (het is een extra, onderzoek punt 3).
  - Tiel-West en Passewaaij zijn regio (91); 04 en 82 lezen dat en
    verwachten het bijpassende gedrag.
  - Familie (K5): alleen code weg (app, website-paneel, niet meer in de
    hook-deploy). Een oud account met rol familie kan niet meer inloggen in
    de app (nette fout) en heeft in het paneel "geen rol". hh_koppelingen,
    de familie-hooks op de server en hun data blijven staan.
  - Beheerpaneel: "Ouder gaf toestemming op <datum>" en "AVP: ja/nee",
    alleen lezen, geen knop.
